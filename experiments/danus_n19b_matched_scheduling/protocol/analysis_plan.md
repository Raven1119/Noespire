# N1.9b Frozen Analysis Plan

The valid-cell target is 18. Integrity or matching failures make the experiment `INCONCLUSIVE`; ordinary mathematical failures remain evidence.

Per run, rederive: solved, workers launched/attempted, verifier accepts/rejects, verified facts, supporting closure, facts outside it, worker/verifier/total tokens, first verified-target time, and terminal wall clock. For C also record worker-1 result, first success index, saved workers, and genuine later recovery. For A record successful worker count, first success index/time, and redundant accepted targets.

Primary comparisons are solve rate, workers and tokens, time to first verified target, and terminal latency. A recovery requires C worker 1 to fail and a later C worker to pass. Parallel redundancy requires A to solve a problem B/C fail, or a clearly material latency/robustness benefit that compensates for compute. Material compute reduction is pre-registered as at least 50% fewer launched workers or observable total tokens than A.

Verdicts use the exact names in the task: `SINGLE_WORKER_FIRST_SUPPORTED`, `DEMAND_DRIVEN_EXECUTION_SUPPORTED`, `SEQUENTIAL_RECOVERY_SUPPORTED`, `PARALLEL_REDUNDANCY_SUPPORTED`, or `INCONCLUSIVE`. The priority for complete valid matched-arm evidence is: an A-only problem solved while both B and C fail; a genuine C recovery; matched demand-driven retention with at least one extra C launch; explicit single-worker retention; compensated twofold first-target latency. If none of those primary rules fires, a frozen dominance fallback ranks arms by higher solve count, then fewer launched workers, then fewer observed tokens, with exact ties ordered B, C, A. Dominant A maps to parallel; dominant C with a later launch maps to demand-driven; dominant B or a one-worker dominant C maps to single-worker-first. This fallback selects the empirically non-dominated scheduling default without relabeling valid evidence as invalid. `INCONCLUSIVE` is reserved for invalid integrity, runtime, problem-set, or cell-count evidence. If A, B, and C all solve 6/6 and every C first worker succeeds, issue `SINGLE_WORKER_FIRST_SUPPORTED` rather than seeking harder problems.
