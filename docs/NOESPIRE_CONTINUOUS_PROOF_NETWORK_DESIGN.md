# Noespire 持续研究驱动的共享证明网络

**英文工作名：** Continuous Research Proof Network（CRPN）\
**状态：** 本次讨论确定的实施设计；不是已实现状态或性能结论\
**范围：** 仅使用 LLM 进行自然语言数学研究、证明与验证\
**实施顺序：** 完成新核心及确定性验证，再开展旧题集真实评估\
**配套任务卡：** 用户的 2026-09-13 `/goal` 消息；用户已确认没有单独的 GOAL 文件。

> 从原始问题开始，以有限注意力进行可接续的局部研究；准确保存命题、证据、开放支持关系和尚未完成的数学工作。程序保证材料曝光、增量连接与公平回访，LLM 选择具体研究动作。AND/OR 图由实际工作逐步长出，不预先预测完整证明结构。

## 1. 设计目标与旧方案替代范围

本设计面向长程、可能长期无法判断目标距离的数学问题。它既允许一次调用直接完成简单命题，也允许一项研究经过多次调用、期间没有新 Fact，最后才形成可复用成果。目的不是设立“发明工具”阶段，而是让新的数学关系、辅助对象和方法有机会在局部工作及其连接中形成。

**冻结以下边界：**

| 项目 | 本设计决定 |
|---|---|
| 数学能力来源 | Selector、Worker、Verifier 都使用 LLM；程序不充当数学求解器 |
| 图的形成 | 先有原始目标；新 Claim、Support、Fact 来自实际局部成果和研究需求 |
| 搜索控制 | 不采用根到叶回溯、MCTS、路径价值回传；允许多个支持方式共存并共享证据 |
| 长程研究 | Study 持续保存接续位置；不是靠一个无限增长的聊天会话 |
| 停止策略 | 不设默认总尝试数、总节点数或连续无进展次数的数学终止条件 |
| 注意力 | 每次调用有完整且有限的工作包；窗口可移动、可按需补读 |
| 验证层级 | 生成 LLM 级自然语言证明；本轮不建设 Lean 或形式验证层 |
| 开发范围 | 新核心、最小正式运行入口、证据与评估适配；不重做前端 |

### 对历史设计的明确修订

| 保留 | 在新路径中替代 |
|---|---|
| FactGraph、content-addressed Fact、真实 predecessors、supporting closure | 先生成完整 Scaffold 再执行 |
| Claim/obligation 数学语义不可原地改写 | 以 SPLIT/CUT/ALT 图重构作为主要推进手段 |
| AND/OR 表示与调度策略分离 | 每个局部失败必须交给结构重构 |
| 有限的单次模型调用、fresh verifier | 某条研究线耗尽累计尝试预算后永久停止 |
| 未验证材料与已验证事实分离 | 仅靠 Facts 与摘要恢复研究，没有精确接续状态 |
| 复用现有执行、持久化和隔离基础设施 | 为新机制重新搭建通用 Agent runtime |

本修订只作用于新的持续研究模式。保留旧核心、历史 tag、原始评估、旧运行状态和原有停止语义，不就地迁移或改写历史证据。以一条简短 ADR 和当前架构入口链接记录这次替代关系；不删除历史文档。

## 2. 数学状态：Claim、Fact、Support、Study

这四者是概念职责，不强制建立四套存储或新类层级。优先映射现有 `ProofObligation`、Route、Fact 和执行记录。

### Claim：一个准确命题

最小信息为 `claim_id`、原文 `statement`、不可变 `scope_ref`。Scope 指向准确的定义、变量域、量词和假设；可以直接复用现有 context identity。

Claim 身份与其某一份证明身份分开。一条 Claim 可以没有证明，也可以有多份有效 Fact。采用现有精确身份规则；不得靠 embedding、大小写折叠、自然语言相似度自动合并命题。新表述通过明确的等价或蕴含证明连接。

原题完整文本是原始目标的依据。研究焦点可以暂时是“怎样控制余项 R”，不要求先把它虚构成一个精确 theorem；这种焦点属于 Study。

### Fact：被接纳的具体证明

复用现有 FactGraph 与接纳入口，保留 statement、proof、实际 predecessors、证据来源及撤销机制。Claim 到 Fact 的绑定可以是派生索引，不必修改旧 Fact 文件格式。

只把本次真正使用的前提写入 predecessors。**可见材料不等于证明依赖：**

\[
K_{\mathrm{used}}\subseteq K_{\mathrm{visible}}.
\]

不要为了适配旧“必须使用全部输入前提”的 executor 而给事实增加虚假依赖。优先在现有提交 seam 之上增加局部适配；旧执行模式及旧 obligation 的 premises 不原地修改。

### Support：一种可连接的支持关系

一个 Support 表达：

\[
\Gamma\vdash(H_1\land\cdots\land H_k)\Rightarrow Q.
\]

最小信息为 `support_id`、`conclusion_claim_id`、`requirement_claim_ids`、`scope_ref`、`bridge_fact_id`。它必须引用一份已验证的条件命题证明；Verifier 同时核对该证明与所登记条件、结论的对应关系，避免“正确证明配上错误边”。无需额外增加一条策略审核流水线。

`bridge_fact_id` 证明的是条件命题，不证明各个 H，也不直接证明 Q。未证 H 只能在显式条件里；不得作为已存在的 Fact 前提。零条件的完整证明可以直接绑定 Claim，无需额外制造 Support。

同一 Support 的条件为 AND；指向同一 Claim 的不同 Supports 为 OR。两个替代支持 `{A,B}⇒T` 与 `{C}⇒T` 不得合并成 `{A,B,C}⇒T`。

Support 的缺口为：

\[
M(e)=\{H\in\operatorname{requirements}(e):H\text{ 尚无作用域兼容的可用 Fact}\}.
\]

`M(e)` 为空时，只产生 LLM 合成任务；合成通过 Verifier 后才接纳结论 Fact。实际 lineage 包含选用的前提 Facts、bridge Fact 以及合成论证真实使用的其他材料。

搜索关系可以有环，但环不能自我启动。`A⇒B` 与 `B⇒A` 没有起点证据时保持等待。最终证据依赖维持现有 Fact DAG。归纳、分类讨论、反证写成带完整量词和假设的有限证明接口，不把局部假设变成全局 Fact。

### Study：持续局部研究及接续位置

Study 是研究状态，不是第三张数学证明图，也不是新增的 verified truth store。最小信息包括：

| 字段职责 | 内容 |
|---|---|
| 身份与焦点 | `study_id`、scope、关联 Claim 或自由研究焦点 |
| 已知材料 | 准确 Fact、定义、对象、原始证据引用 |
| 当前接续状态 | 当前推导、尚未解决的条件、做到的位置、下一项可继续工作 |
| 索引卡 | 给 Selector 看的简短研究卡及其原文引用 |
| 历史 | 不可变 revision、最近服务位置、实际调用与反馈 |

**索引卡与接续材料分离。** 卡片可概括，数学工作必须能返回准确原文。Study 中的未完成推导、猜想、试例和候选界明确标为未验证；它们不能进入下游 accepted-predecessor 区域。

每次正常局部调用可以只更新 continuation，不必产出 Fact。即使 Verifier 拒绝候选，仍保留明确可接续的研究记录与具体反馈。失败不会自动证明候选命题为假。

只保存模型显式返回的数学笔记和结构化接续产物，不依赖隐藏推理、未返回的中间状态或无限会话。超时未获得新输出时，从最后一份已持久化接续状态恢复，记录丢失本次进展；不得伪称能恢复没有收到的内容。

## 3. 局部执行与开放接口

只有三个语义角色：Research Selector、局部 Worker、fresh Verifier。可以共享同一模型和调用适配器；不增加全局 Architect、Value 模型、策略保真度审核器或新失败诊断 Agent。

局部 Worker 的操作模式为：

| 操作 | 工作内容 |
|---|---|
| `ADVANCE` | 继续某个 Study、直接证明当前命题、推导局部后果或调查障碍 |
| `CONNECT` | 有限联看几个准确接口，尝试组合、消元、实例化、新表示或辅助量 |
| `COMPOSE` | 某个 Support 的条件齐备，写出对应结论的合成证明 |

它们是工作接口，不是穷举数学技巧的固定规则表。反证、例子、归纳、换表示等由 LLM 按任务选择，不写成 Python 数学策略分类器。

一次调用可以返回：一个候选完整成果、一个带完整论证的条件成果、更新后的 continuation、指定的补读请求，或 `NO_PROGRESS`。可同时返回 continuation 和一个候选成果；初版以一项候选为默认粒度，不强迫每行证明都建节点。

条件关系获 PASS 不等于证明难度下降。`T⇒T` 或一串不断转移缺口的条件命题不获得额外关注配额。它们可以精确去重，实际是否值得继续由后续研究评价决定；不设置“条件减少”的强制单调进度条件。

**开放关系示例：** `E' + D ≤ R` 本身可完整证明，虽然 R 尚无法控制。保存该 Fact，登记关于 R 的 Study。后续得到 `R=A-B` 或 `R≤αD+S`，再安排相关联看。系统不预先承诺这些关系最终如何闭合。

新数学对象的定义必须以不可变文本和 scope/version 保留。定义不自动蕴含对象存在、具有所需性质或能满足某个约束；这些仍需局部证明。程序的对象 ID 用于检索和引用，不进行数学等价推断。

## 4. 有限注意力与可移动工作窗口

### 工作包

每次 Worker 输入只含本次目标/焦点、必要的准确定义和假设、选择的 Fact 陈述、相关 continuation、具体新证据及必要的最近反馈。Selector 读取少量研究卡和证据引用，Verifier 读取局部数学接口，不读取选择该方向的策略叙事。

默认不传整图、不传全研究历史、不递归注入全部前驱证明。下游可以使用已接纳 Fact 的完整陈述；要使用证明中未在陈述公开的性质，必须显式提取并验证它。

本地工作包与验证包分别有容量设置。容量采用当前调用适配器可获得的实际 token 计数；只能估计时标注估计方法，不宣称已测真实 token。不得静默截断假设、量词、参数依赖和证明正文。

### 补读与联看

`NEED_CONTEXT` 指向具体对象、定义或证据片段。程序补读本地持久材料；请求不涉及网络文献搜索或数学工具。

材料太大时，由 LLM 改变工作窗口、分次推导，或证明一个更短的中间接口。摘要只是导航，不能代替已省略的数学条件。固定的“最多几个 Fact”不能成为所有证明的永久宽度上限。

维护简单 `object_ref → Study/Fact` 索引以及词面检索即可启动。由相似性找到的材料只是候选；同名不同对象、不同见证和不同参数范围不能自动拼接。无已知共享对象的跨区曝光由探索通道处理。

## 5. 选择策略：LLM 评价动作，程序保证曝光

### 三种选择通道

通道决定“哪些材料获得注意”；上一节操作决定“拿到材料后做什么”。不要把二者合成一个 if/else 数学策略机。

| 通道 | 曝光来源 | Selector 的决定权限 |
|---|---|---|
| 推进 | 条件就绪的 Support、新证据关联的 Study、正在延续的推导 | 在有限候选中选择本次最具体可做的局部动作 |
| 探索 | 未充分关注的对象、工作变体、没有现成依赖的区域组合 | 提出一项研究工作；允许与目标的连接为 `UNKNOWN` |
| 回访 | 程序持久轮转选中的旧 Study | 只能决定怎样研究该焦点，不能因“价值低”改去热门方向 |

Selector 的判断依据为推进价值、辨别障碍的价值、形成新接口的价值。输出所选焦点、操作、材料引用、证据性理由和关系未知标记即可；不制造目标距离或未经校准的成功概率。

**3:1:1（推进/探索/回访）是实验初始排班，不是已证明最优比例。** 配置和排班游标持久化。三通道在有可服务材料时持续获得调用机会，探索与回访份额不能因低评分降至零。空推进队列可转去探索/回访，不能误判整项研究耗尽。

### 公平回访

每轮回访开始时取得未完成 Study 的有限快照，保存顺序和游标。每个回访时段推进一个焦点；该焦点获得一次真实局部研究，不只是进入 LLM 候选池。新 Study 加入下一轮，不插队；已完成或用户明确停用的 Study 可跳过并留记录。

在局部调用能结束、回访时段持续运行的条件下，快照内每项工作都会得到服务。这只约束已登记工作的曝光，不宣称证明完备性。

普通延续写入原 Study，不靠改名或生成更多 Claim 为同一研究线增加回访席位。初版用稳定 Study identity 和明确 `continues_study_id`，不建设昂贵的语义去重引擎。真正独立的新焦点可以新建，不设置永久总数量封顶。

### 未知连接的探索曝光

不能只将相关性 Top-K 交给 Selector。探索时交替提供未充分研究的单个区域和不同区域的准确接口样本。允许从有限持久快照用独立于价值评分的轮转或可复现采样取材，并记录 seed/游标；不要求一次枚举全图两两组合。

Selector 可以提出“没有关联”的研究结果，但不能把 UNKNOWN 永久移出材料池。索引卡需能回读原文，旧材料应可在后来被重新理解。

### 去重与再次尝试

同一 Study、同一操作、相同证据与 continuation revision 的机械重复事件去重。显式研究、回访或探索可以再次处理相同焦点，必须有新的 visit/call identity 并记录实际结果。**事件去重不能变成禁止旧焦点再次研究的总闸门。**

LLM 可以因重复无新增内容降低推进通道中的优先级，但不能因此撤销事实、判定命题为假或剥夺回访机会。一次没有 Fact 不必是无进展；一次新增长笔记也不自动是进展。

## 6. 运行、持久化与恢复

### 两种边界不能混淆

| 边界 | 行为 |
|---|---|
| 单次注意力/调用时间 | 有限；一次工作结束、补读、让出调度，或记录调用故障 |
| 累计研究长度/失败数/节点数 | 新核心不设置默认数学终止阈值 |
| 用户暂停、资源不可用、外部评估观察点 | 保存状态后暂停；目标仍 OPEN；可以 resume |

不得把旧 v3 的 `24/6/12/12` 或 per-route 三次上限原样继承为新模式的研究寿命。旧模式仍按其冻结约束工作。局部 solver 可以复用其单轮能力；一轮耗尽不等于对应 Study 永久 EXHAUSTED，也不强制进入图重构。

需要暂停/恢复、只读 status 和调用成本记录。不在本轮建设分布式常驻服务。资源故障可以暂停 run，但不能自动禁用该研究焦点；恢复后继续已登记的工作。

### 最小持久化契约

优先复用当前原生存储和 journal，不预设第二份 canonical `proof_graph.json`。保存四类内容：数学图和 Fact；Study 各版本及原始材料；调度快照/游标和待办；调用请求/显式返回结果/应用记录。

单 workspace 单执行所有者。一次局部返回先持久化，再验证/接纳，再更新研究索引和队列；用现有幂等调用及事件标识恢复。已经确认保存的 Worker、Verifier、Selector 结果不因重启重跑，已接纳 Fact 不重复创建，回访游标不归零。

进程中断造成未确认调用时，沿用原调用的 interruption evidence；从最后确认状态恢复或显式标记重新尝试，不声称远端调用 exactly-once，也不伪造未返回的数学进展。累计 usage、失败与已服务历史不清零。

已保存的研究数学语义通过新 revision 变更，不覆盖旧记录；更改运行代码或模型配置时复用现有 fingerprint/明确 continuation 机制，不悄悄跨版本 resume。

## 7. 主循环与证明完成

```text
登记原题 Claim 与初始 Study
→ 首先允许一次直接证明，不支付整图规划成本
→ 循环：
    程序确定推进 / 探索 / 回访通道及可见材料
    Selector 决定本次局部研究动作
    恢复 Study，构造完整的有限工作包
    Worker 显式返回研究更新及可选候选成果
    持久化接续材料与 attempt
    若有候选：机械引用检查 → fresh Verifier → Fact 接纳
    若有条件证书：绑定 Support，并登记剩余需求
    增量更新相关 Study / Support，持久化调度位置
→ 原目标已有可用 Fact：提取并导出其 supporting closure
→ 用户或资源要求暂停：保存状态，保持原目标 OPEN
```

原题没解决时，队列暂时没有已就绪证明任务不算研究终止；可以继续研究原目标、回访旧焦点或调查新关系。环境完全无法执行时进入有原因的暂停，不忙等。

最终证明沿具体证据依赖导出，包含准确 statement、proof、定义与引用。不会把所有探索笔记塞进最终正文，也不要求全局统稿模型再次读完整篇超长证明。

本轮输出标准就是 LLM 级自然语言证明。继承 Fact/Refutation 的已有语义；不为未来形式化增加额外架构或新审核团队。

## 8. 最小工程形态与验证

### 模块职责

优先复用本地当前核心。逻辑上只需三个增量职责：

| 职责 | 主要工作 |
|---|---|
| 共享数学网络 | Claim/Support 与现有 ProofGraph/FactGraph 绑定、尚缺条件和增量连接 |

### 观察窗口不成为研究终止策略

真实评估不能无限占据一台机器。阶段 B 开始前，在新协议中固定整组统一的观察时刻或计算快照口径，并使用外层 observer 暂停新 run；目标仍 OPEN，Study 与游标完整保留，后续可 resume。它不是引擎内部“次数耗尽即结束”。

记录 Selector、Worker、Verifier、修正、补读涉及的全部模型开销；复用旧后审计时单列其成本。结果至少包含逐题目标状态与证据、tokens/调用/时间、最大局部上下文、continuation 接续、跨 Study 复用、探索/回访实际服务、暂停恢复及未完成原因。节点数不是主指标，未知 usage 不填零。
