## Exact upstream behaviors relevant to Phase 0A

1. **Identity and storage are separate concerns.** Danus hashes normalized semantic payload fields, not the rendered Markdown bytes. Changing author attribution does not change the ID; changing statement, proof, problem, or predecessor set does.
2. **Predecessor order is not identity-bearing.** Danus sorts predecessor IDs for hashing. The stored frontmatter preserves the supplied list, while closure/topological ordering is derived mechanically.
3. **Verification and persistence are separated.** The fresh verifier only judges and returns JSON. The worker-facing submission path owns the accepted-only graph write.
4. **Fresh means a new Codex process/session.** Danus invokes `codex exec` for every verifier request; it does not reuse the research worker's context.
5. **Closure follows only explicit graph edges.** It recursively follows persisted predecessor IDs. It does not use embeddings, statement similarity, graph matching, or model judgment.
6. **The upstream core graph has no first-class closure method.** The proven traversal is `_toposort_with_predecessors` in `write_paper/assemble.py`; Noespire's `supporting_closure` is a Phase 0A API placement decision around that established behavior.

## Deliberately not borrowed in Phase 0A

Danus's glossary system, external-reference audit metadata, BM25 search, global/local memory tiers, revocation machinery, role-gated MCP server, swarm orchestration, autonomous round loop, deterministic verifier prechecks, arXiv integration, paper assembly, and dashboards are outside this experiment. Their absence is intentional and does not imply replacement designs.
