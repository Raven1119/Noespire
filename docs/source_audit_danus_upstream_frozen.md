## Installation

- The official installation path is `bash scripts/bootstrap.sh`; it provisions a self-contained runtime under the gitignored `runtime/` directory ([`README.md:109-128`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/README.md#L109-L128), local `baselines/danus/README.md:109`).
- Required host prerequisites are Linux, Git, Python 3.10+, curl, tar, and bash. The bootstrap creates the Python venv, installs the package editable, and installs the Codex CLI ([`docs/getting-started.md:7-17`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/docs/getting-started.md#L7-L17), [`docs/getting-started.md:19-37`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/docs/getting-started.md#L19-L37)).
- Python package metadata requires Python `>=3.10`; the core package has no mandatory dependencies, while gateway/verify/dev dependencies are optional extras ([`pyproject.toml:19-40`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/pyproject.toml#L19-L40), local `baselines/danus/pyproject.toml:19`).

## Main problem/theorem run entry

- The interactive top-level entry is Codex launched from the DANUS repository root with `codex --dangerously-bypass-approvals-and-sandbox`; the root `AGENTS.md`, `.codex/config.toml`, and `.agents/skills/` define the main-agent runtime ([`README.md:122-128`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/README.md#L122-L128)).
- A project is created by placing the verbatim goal in `runtime/projects/<p>/PROBLEM.md` and running `danus new <p> --roles high:N,xhigh:M` ([`docs/operating-guide.md:32-43`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/docs/operating-guide.md#L32-L43)).
- Worker proof search starts with `danus start <p>`; workers read `TASK.md` plus `master_guidance` and submit candidate facts through the verifier-gated `fact_submit` tool ([`docs/operating-guide.md:64-75`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/docs/operating-guide.md#L64-L75)).
- `bin/danus` is the shell wrapper for `python -m danus.orchestration`, whose CLI implements `list/new/assign/finalize/start/status/stop` ([`danus/orchestration/README.md:1-11`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/orchestration/README.md#L1-L11), [`danus/orchestration/cli.py:375-410`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/orchestration/cli.py#L375-L410)).

## Model/provider configuration

- Backend credentials and provider selection are copied from `config/codex.env.example` to the gitignored `config/codex.env`; the API profile uses `CODEX_BACKEND`, `CODEX_API_BASE_URL`, `CODEX_API_MODEL`, and `DANUS_CODEX_API_KEY`, while ChatGPT login is the documented alternative ([`config/codex.env.example:1-24`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/config/codex.env.example#L1-L24)).
- General model selection lives in `config/danus.env`: `DANUS_MAIN_MODEL`/`_EFFORT` are neutral defaults, `DANUS_WORKER_MODEL` is the worker override, and `DANUS_VERIFY_MODEL`/`_EFFORT` are verifier overrides ([`config/danus.env.example:23-35`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/config/danus.env.example#L23-L35)).
- The frozen `codex` branch's main-agent configuration is `.codex/config.toml`: model `gpt-5.6-sol`, reasoning effort `ultra`, and the DANUS MCP server runs with `DANUS_ROLE=main` ([`.codex/config.toml:6-8`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/.codex/config.toml#L6-L8), [`.codex/config.toml:31-39`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/.codex/config.toml#L31-L39)).

## Verifier configuration and entry

- The verifier implementation is `danus/verify/`: `prechecks.py` performs offline hard prechecks, `launcher.py` cold-starts Codex, and `service.py` exposes the FastAPI `/verify` and `/health` routes ([`danus/verify/README.md:38-46`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/README.md#L38-L46)).
- The direct service entry is `python -m danus.verify` on `127.0.0.1:8091` ([`danus/verify/README.md:48-58`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/README.md#L48-L58)); deployment instructions prefer `bash scripts/services.sh up verify`, and state that facts cannot be produced without it ([`docs/getting-started.md:77-84`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/docs/getting-started.md#L77-L84)).
- Verifier host/port, agent/run directories, Codex binary, model/effort, timeout, and precheck thresholds are environment variables documented in [`danus/verify/README.md:61-72`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/README.md#L61-L72). `fact_submit` sends `{statement, proof}` to `DANUS_VERIFY_URL` and persists a fact only for `verdict == "correct"` ([`danus/verify/README.md:74-78`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/README.md#L74-L78)).

## Primary engine modules

- Fact Graph: `danus/core/factgraph.py` defines `FactGraph`, rooted at a project directory and described as the correctness source ([`danus/core/factgraph.py:110-114`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/factgraph.py#L110-L114)). Its sibling `schema.py` defines Fact/content IDs; `local_memory.py` and `global_memory.py` implement the other memory tiers ([`danus/core/README.md:13-21`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/README.md#L13-L21)).
- Worker engine: `danus/execution/layout.py`, `scaffold.py`, and `loop.py` own layout, project/worker creation, and the per-worker round loop ([`danus/execution/README.md:1-14`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/README.md#L1-L14)); the executable functions are `run_round` and `main` in [`danus/execution/loop.py:130-188`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/loop.py#L130-L188).
- Orchestration: `danus/orchestration/cli.py` is the lifecycle CLI and `danus/orchestration/__main__.py` is its module entry ([`danus/orchestration/README.md:1-11`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/orchestration/README.md#L1-L11)).
- Truth write-gate: `danus/gateway/server.py:fact_submit` is the gateway seam between workers, verifier, global-memory trace, and Fact Graph ([`danus/gateway/server.py:150-235`](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/gateway/server.py#L150-L235)).
